# SaveMod на Rust

Бот для Telegram Business: сохраняет переписку, замечает удалённые и
изменённые сообщения, выгружает историю в автономный HTML-архив и
принимает выгрузки Telegram Desktop.

**Ноль внешних зависимостей.** Только `std` и системный `libcurl` —
поэтому сборка проходит где угодно, без crates.io и без интернета.

## Что внутри

| Файл | Назначение |
|------|------------|
| `src/main.rs` | точка входа, long-polling, устойчивость к падениям |
| `src/handlers.rs` | команды, кнопки, оплата, Business-события, админка |
| `src/menus.rs` | тексты экранов с кастомными эмодзи |
| `src/keyboard.rs` | inline-клавиатуры, защита от «мёртвых» кнопок |
| `src/sender.rs` | отправка меню с баннером и фолбэками |
| `src/api.rs` | клиент Bot API (sendPhoto, editMessage*, invoice, Business) |
| `src/store.rs` | хранилище на JSON-файле, AES-256-GCM для текстов |
| `src/archive.rs` | экспорт HTML, импорт `result.json` и ZIP (со своим inflate) |
| `src/http.rs` | HTTPS через libcurl FFI (multipart, таймауты) |
| `src/crypto.rs` | SHA-256, AES-256, GCM — проверено векторами FIPS/NIST |
| `src/json.rs` | JSON парсер/сериализатор |
| `src/emoji.rs` | `<tg-emoji>` и деградация без права на кастомные эмодзи |

## Сборка и запуск

```bash
cd rust
./build.sh          # cargo build --release
cp ../.env.example ../.env   # вписать BOT_TOKEN и ADMIN_IDS
./run.sh
```

Нужен только Rust 1.70+ и `libcurl` (в Debian/Ubuntu: `apt install libcurl4`).
`build.rs` сам находит библиотеку — симлинк `libcurl.so` не требуется.

## Тесты

```bash
cd rust
./test.sh
```

97 тестов: 86 юнит, 2 в точке входа и 9 интеграционных.
Интеграционные поднимают **фейковый сервер Telegram** (`tests/fake_telegram.rs`)
и прогоняют через него настоящие обработчики — в том числе боевые отказы:

* `DOCUMENT_INVALID` на кастомные эмодзи → бот повторяет без них;
* `there is no text in the message to edit` → бот отправляет новое сообщение.

## Баннеры

Лежат в `../assets/`, имена — ровно как в конфиге:

```
main         → assets/mainmenu.jpg
settings     → assets/settings.jpg
subscription → assets/subscription.jpg
admin        → assets/adminmenu.jpg
```

Перед отправкой файл проверяется по сигнатуре JPEG/PNG/GIF/WEBP. Если его
нет или это не картинка, меню уходит текстом — бот не падает и не молчит.
То же самое, если Telegram отклонит фото: пользователь всё равно увидит меню.

## Меню и кнопки

Главное меню: `Тарифы` | `Пригласить друга`, затем `Подключение`,
затем `Настройки`; у админа последним рядом — `Админ-панель`.
Кнопки **«Создать бота» больше нет** — она убрана из всех меню и текстов.

`callback_data` всегда лежит в отдельном поле и никогда не совпадает с
подписью кнопки: иначе Telegram подменяет данные и кнопки перестают работать.

## Telegram Business

Бот не может сам включить Business-режим — это делается владельцем аккаунта
в настройках. Бот принимает:

* `business_connection` — включение/выключение, сохраняется в базе;
* `business_message` — переписка (шифруется, кладётся в архив);
* `edited_business_message` — правки;
* `deleted_business_messages` — удаления (помечаются, владелец получает уведомление).

Команды владельца прямо в Business-чате:

```
.nah     — отключить перехват
.love    — включить перехват
.bypass  — скрыть перехват для собеседника
.mute    — выключить уведомления
.unmute  — включить уведомления
```

Точка или запятая от собеседника включают перехват сгорающих медиа.

## Кастомные эмодзи

Telegram разрешает кастомные эмодзи (`<tg-emoji emoji-id="…">` и
`icon_custom_emoji_id` в кнопках) только ботам с юзернеймом, купленным на
Fragment, либо если у владельца бота есть Premium. Иначе Bot API отвечает
`DOCUMENT_INVALID` / `BUTTON_ICON_INVALID`.

Бот это переживает: при таком отказе эмодзи отключаются на весь процесс,
а меню переотправляется с обычными. Пользователь никогда не остаётся
без ответа — именно этот сценарий ронял прежнюю версию.

## Оплата

Звёзды Telegram (XTR), суммы проверяются до подтверждения платежа:

| Тариф | Звёзд |
|-------|-------|
| 7 дней | 25 |
| 30 дней | 75 |
| 90 дней | 150 |
| Премиум, 365 дней | 300 |

Если сумма не совпадает с тарифом, `pre_checkout_query` отклоняется с
понятной причиной — деньги не спишутся.

## Архивы

**Экспорт** — один самодостаточный HTML-файл: стили внутри, ничего не
подгружается из сети, весь текст экранирован (`<script>` из чужого
сообщения не сработает). Можно выбрать типы сообщений.

**Импорт** — `result.json` из Telegram Desktop или ZIP с ним. ZIP
распаковывается собственным inflate, запись с `../` в имени блокируется
(zip-slip), размеры ограничены.

## Формат базы

JSON-файл, запись атомарная (временный файл + rename). Тексты сообщений,
имена и подписи хранятся в `enc:v1:<nonce>:<tag>:<payload>` (AES-256-GCM,
base64). Старые записи открытым текстом читаются как есть, поэтому базу
прежних версий можно использовать без миграции.
